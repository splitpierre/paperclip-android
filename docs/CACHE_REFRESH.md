# Cache saved reads and keep foreground refresh workers alive

- Screen loaders now keep one refresh running and coalesce invalidations into at most one follow-up. A timer or live event cannot cancel a slow load. Foreground loaders, event listeners and fallback polling follow the STARTED lifecycle.
- Duplicate 15/20-second polling was replaced by one 20-second fallback per active screen. Task syncing stops when the app backgrounds. Identical simultaneous API GETs share one in-flight request; an already-started shared GET may finish to populate the cache after its screen closes.
- A private SQLite snapshot cache persists reads across process restarts. It is partitioned by server, authenticated account and credential, with company/query scope in the resource key. It retains at most 128 snapshots, 32 MiB of JSON payload and seven days of data; individual entries over 1 MiB are not cached. A stored UTF-8 byte count enforces the budget without scanning JSON bodies after each write; existing caches compute sizes once during migration. SQLite may retain allocated file pages after eviction. This is an application data cache, not a forced HTTP response cache.
- Screens try saved data first and then revalidate. Shared-loader screens label cached content. Bootstrap can restore a previously authenticated local account and cached company while validation is unavailable. Writes still require the server. Successful mutations invalidate snapshots; read receipts do not clear the entire data cache. Bootstrap metadata survives routine invalidation. Sign-out deletes the account's snapshots and forgets its saved identity. Account changes remount screen state.
- Startup reuses the session response and shows the shell before optional lookups finish. Lookups and dashboard requests run concurrently. Task labels reuse the task mirror when possible.
- Task initial sync publishes pages incrementally. Delta sync drains all keyset pages, uses a conservative server-time watermark and periodically reconciles complete snapshots to remove deleted rows. Reconnect requests a delta; deletion events and the five-minute interval request full reconciliation. Without a server sync cursor/deletion feed, reconciliation remains eventual, not a transactional snapshot guarantee.
- WebSocket reconnection follows network changes, adds jitter and requests reconciliation when the event buffer overflows. API calls have a total timeout. Superseded session/company responses are discarded with a dedicated exception, keeping refresh workers alive. Actual cancellation is propagated through optional-load helpers, and cancelled HTTP response handoffs close their bodies.
- `NetworkMetrics.snapshot()` provides up to 100 in-memory request samples: total time, time to complete response headers, response bytes, status and failure. It stores no URL, credential, header or body. It is diagnostic infrastructure, not exported telemetry.

Run `./gradlew :app:testDebugUnitTest` with a complete JDK 17+ and Android SDK. Robolectric tests verify storage and Compose behavior, not physical-device frame rates.

Regression tests cover stale responses followed by successful refreshes without restarting the lifecycle, actual cancellation propagation, cache size migration and byte eviction, oversized responses bypassing persistence, healthy sockets surviving network callbacks, and draining more than 1,000 task changes. The task mirror stays in this PR because its session, cache and lifecycle ownership are integrated with app bootstrap; task graph and UI work is separate.

Agent and project lookups index each immutable directory snapshot once instead of scanning the full directory for every visible row. Refreshing or clearing the snapshot replaces the index. A regression test verifies one directory pass across 1,000 row lookups and checks rename, deletion and company-clear behavior.

The issue screen’s header, pending interactions and comment/interaction timeline have separate lazy-list content types. This screen change stays with its loader/lifecycle fixes so the independent transcript contribution merges without overlapping edits.
